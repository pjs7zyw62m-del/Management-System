# Live website updates
The browser polls the deployed same-origin blackcell-site-version.json every 30 seconds while visible. GitHub Pages/Jekyll renders the build revision or build timestamp. If the production host serves the template raw, increment the fallback value with every future release. No polling of unpublished commits.
All enabled pages automatically refresh without a prompt after 12 seconds of inactivity, only when no tracked unsaved changes, active operations, or open modal are present. Pending releases are retried silently every two seconds. The updater keeps the exact browser URL and valid auth session, restores window scroll and identified scroll containers best-effort. No passwords, account info or drafts are persisted. Dynamic UI without URL state is not restored. Apps can use BLACKCELL_LIVE_UPDATE.hold(reason) (returns release function) to explicitly block reload during async work and clean(element) once edits are saved. The animation is indeterminate. Browser and deployment testing are required.

The updater also holds active cinema sessions (including pause), visible streaming players, in-progress video/audio, and explicit upload wrappers for social posts, movie uploads, photo collections, chat media, Bunny/B2 bulk batches and private photo ledger uploads. Active operations defer the refresh silently; closed cinema and completed operations release their holds. The existing media administration busy marker is respected. These are in-browser safeguards, not durable resumable-upload or movie-position persistence. Reloading or closing the browser manually can still interrupt work.
