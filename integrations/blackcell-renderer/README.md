# BLACKCELL private rendering pilot

FFmpeg VOD HLS; original bytes are never replaced. 360p–2160p renditions are supported, no upscaling, 4-second keyframe-aligned segments, default maximum 1080p to control costs. Pilot handles approved, rights-confirmed, non-adult World library videos only. Paid cinema is unchanged.

## Deployment gates (do not enable public traffic yet)
1. Provision a private Linux cloud container with FFmpeg, FFprobe, Python 3.11+ and at least 2 vCPUs, 4 GB RAM and bounded temporary disk. Run one worker only, with no inbound ports. Build the included Dockerfile, review/pin the base image digest before production, and inject secrets from the cloud provider's secret manager, never into GitHub or a browser.
2. Set SUPABASE_URL, BLACKCELL_RENDER_CATALOG_READ_KEY (server-only catalog access; prefer a restricted credential/read-only broker, not a broadly privileged project key), and BLACKCELL_BUNNY_STORAGE_ACCESS_KEY. Run worker.py --max-jobs 1 --max-height 720 initially. No rendering is performed until this worker runs. Confirm the original byte count and storage objects; check the readiness marker under the private blackcell-renders/v1 prefix. Then pilot --poll 300 with a bounded batch. One worker only; establish idempotent retries, dead-letter handling, cleanup of incomplete generations, quotas, retention and alerting before larger batches. A failed run does not publish a ready marker.
3. Deploy blackcell-render-playback as a separate authenticated Edge Function with JWT/session verification, existing server-side storage credential and no public access. Do not replace blackcell-world-media. Test authorized, unauthorized, signed-out, revoked-session, unpublished, missing-asset and malformed-path requests; verify HLS manifests/segments from the correct generation. No database schema changes required by the pilot. Repeated per-segment authorization costs and Supabase egress must be measured. Native Safari without MediaSource needs a separate authenticated native-HLS delivery design; the current fallback stays original.
4. Vendor the reviewed, exact hls.js 1.7.4 production distribution at vendor/hls-1.7.4.min.js with its license, integrity checksum and package-lock recorded. Never fetch executable player code from an untrusted CDN. Set BLACKCELL_ENABLE_RENDER_PLAYBACK=true only after the vendor library and authenticated endpoint are deployed and verified. By default this flag is unset and existing original playback stays in place. Auto and manual quality options appear only when the returned HLS manifest contains actual variants. On failure the existing original playback path is used. Test desktop, iPad and iPhone before wider release; Original selection returns to original playback until the video is reopened.
5. Pilot with one video, measure time to first frame, stalls, rendition switching, dropped frames, seek behavior, CPU and storage cost. Then validate multiple users and uploads. The existing native range-streaming PR is separate; this branch does not deploy it. Standard post video, Shorts and chat rendering integration are subsequent scope.

## Local synthetic test
Use testsrc2 (no private media). Generate a five-second 1280x720 24 fps MP4 with sine audio, run render.py input.mp4 output --max-height 720, check 360/480/720 output dimensions, matching 4+1 sec segment durations and ENDLIST, and verify the input hash is unchanged. A component-level FFmpeg command test passed for those three resolutions; cloud end-to-end delivery and browser tests have not run.
